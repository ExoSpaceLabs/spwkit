# SpWKit v0.6.1

SpWKit v0.6.1 is a maintenance and performance-consolidation release on the v0.6 software contract. It preserves the existing public application/backend API while completing the profiling infrastructure, incorporating accepted transport/readiness optimizations, and synchronizing the post-v0.6 documentation.

## Profiling infrastructure

The profiling campaign now records sufficient environment and backend-coverage metadata to make controlled runs comparable and incomplete coverage explicit.

Result sets record, where available:

- OS and kernel;
- architecture and CPU model;
- compiler/version and build type;
- git SHA;
- counter kind and frequency;
- CPU affinity, governor and priority context;
- explicit `unknown` values rather than inferred data.

Backend coverage distinguishes:

```text
measured
unsupported-platform
not-built
not-implemented-benchmark
```

This completes the work tracked by #171 and #173.

## Accepted performance work

### VSPW-TP reassembly

Profiling identified byte-granular fragment-coverage bookkeeping as the dominant 4 KiB RX cost once VSPW-TP crossed its 1200-byte fragmentation threshold.

The optimized normal non-overlapping fragment path reduced the isolated reassembly component by approximately **96-97%** in the controlled i7-10850H campaign.

The production paired `SpWKit - native` RX overhead at 4096 B changed from:

```text
60,281 -> 25,032 invariant-TSC ticks
```

This is a **58.5% reduction** in the measured software/transport overhead for that controlled host and benchmark boundary.

### POSIX UDP readiness

The POSIX UDP backend now attempts optimistic nonblocking `sendto`/`recvfrom` on hosts exposing `MSG_DONTWAIT` and falls back to the existing readiness/deadline path only when the socket would block.

The change preserves timeout, retry, liveness, fault-injection and Windows/Winsock behavior. Hosted before/after jobs landed on different-speed runners, so absolute TSC values are not directly comparable. Normalized paired results showed approximately **10-18% relative transport-overhead reduction** across representative payloads.

### Linux DEVICE/VSPD readiness

Linux DEVICE/VSPD ready-record I/O now attempts nonblocking `send`/`recv` before `wait_fd()` and falls back on `EAGAIN`/`EWOULDBLOCK`, preserving record atomicity, deadlines, disconnect and immediate-timeout semantics.

The direct VSPD comparator uses the same equivalent readiness strategy, and a separate paired AF_UNIX `SOCK_SEQPACKET` microbenchmark measures the removed poll-first cost.

Hosted final-head measurements showed approximately:

```text
TX: 836-850 TSC ticks removed, 40.8-44.9% raw ready-record reduction
RX: 813-840 TSC ticks removed, 45.4-51.0% raw ready-record reduction
```

All eight representative readiness medians improved. These hosted measurements are regression/informational evidence, not universal timing specifications.

## Existing hardware evidence carried forward

The v0.6 evidence boundary remains unchanged:

- physical NUCLEO-H755ZI-Q qualification executes real DMA2 memory-to-memory transfers and explicit Cortex-M7 D-cache synchronization through `SPW_BACKEND_DRIVER`;
- copied and zero-copy ownership paths and reset-time stale-buffer invalidation pass;
- the immutable CCSDSPack external integration baseline remains `v2.0.0`, commit `c2f318c330c564429bcc565a8acbff22728b2851`;
- physical STM32 DMA/cache evidence is not presented as SpaceWire controller, Data-Strobe, PHY, cable, or electrical interoperability evidence.

## Documentation synchronization

v0.6.1 synchronizes stale post-v0.6 material, including:

- stable package/examples from v0.5-era wording to the v0.6 line;
- STM32 runtime evidence from pending to completed while preserving the physical-SpaceWire stop line;
- CCSDSPack wording from provisional/develop-based to the immutable v2.0.0 baseline;
- Linux DEVICE reusable contract documentation;
- `SPW_DRIVER_CONFIG_INITIALIZER(&ops, &context)` usage;
- release `workflow_dispatch` recovery behavior;
- version-neutral public-header comments;
- profiling/current-status pages with the later UDP and DEVICE readiness work.

## Scope deliberately not claimed

v0.6.1 does not claim:

- physical SpaceWire controller/codec/PHY timing;
- Data-Strobe/LVDS interoperability;
- FPGA or ASIC latency;
- router forwarding performance;
- cycle-accurate physical-link simulation;
- formal ECSS certification.

Those remain separate evidence layers.

## Distribution

The exact `v0.6.1` release boundary is promoted only through the repository's `develop -> main` release policy. The accepted `main` head is tagged immutably and the Release workflow publishes validated Debian packages plus SHA-256 files for `amd64`, `arm64`, `armhf`, and `riscv64`, together with the multi-platform GHCR runtime image.

The release leaves the long-lived `main` and `develop` branches as the project integration/release lines; temporary release branches are disposable after integration.
