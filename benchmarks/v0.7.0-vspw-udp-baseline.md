# VSPW-TP/UDP pre-transport-refactor baseline

## Purpose

This record freezes the pre-#229 VSPW-TP/UDP software baseline required by #230 before transport-provider extraction begins.

The comparison boundary is intentionally the existing public operation against a direct same-process UDP socket. These values characterize the current virtual transport/software stack. They are not physical SpaceWire timing claims.

The controlled release-acceptance evidence remains `benchmarks/v0.7.0-performance-evidence.md`. The numbers below preserve the reproducible hosted screening distribution needed to recognize large transport-refactor shifts; they do not replace controlled-host evidence.

## Fixture and protocol configuration

The baseline is defined by `benchmarks/profile_udp_comparison.c` and `benchmarks/run_udp_comparison.sh` at `v0.7.0`.

VSPW-TP/UDP fixture:

- carrier: IPv4 UDP over loopback;
- provider fixture: same-process loopback UDP;
- SpaceWire terminator: `EOP`;
- `fragment_payload_size = 1200` bytes;
- `ack_timeout_ms = 20`;
- `max_retries = 3`;
- `keepalive_interval_ms = 1000`;
- `peer_timeout_ms = 5000`;
- public send/receive timeout: `500000` microseconds;
- benchmark payload capacity: 4096 bytes;
- raw comparator: direct UDP socket send/receive;
- sample order: native-first and SpWKit-first alternating per iteration;
- counter floor is recorded and is not subtracted.

The 4096-byte case exercises VSPW fragmentation/reassembly with the 1200-byte fragment payload. The 0, 64, and 1024-byte cases remain unfragmented.

## Canonical controlled pre/post comparison for #229

After the transport-provider refactor exists, compare the feature candidate directly with immutable `v0.7.0` on the same controlled host:

```bash
bash benchmarks/run_release_profile_comparison.sh \
  --baseline-ref v0.7.0 \
  --candidate-ref HEAD \
  --cases all \
  --warmup 256 \
  --iterations 1024 \
  --payloads "0 1 8 64 256 1024 4096" \
  --cpu auto \
  --governor performance
```

Run at least three complete baseline/candidate pairs on the same otherwise-idle host, preserving the repository's existing release-performance discipline.

For #229, review at minimum:

- UDP TX/RX `SpWKit - native` overhead for every payload;
- the 4096-byte fragmented path separately from unfragmented paths;
- provider-dispatch cost once the transport interface exists;
- VSPW encode/decode, ACK/retry and reassembly stage costs;
- copy count and buffer ownership transitions;
- end-to-end transport jitter only as a separately named metric.

A refactored UDP path is not accepted merely because its absolute latency looks reasonable. Any recurring delta relative to `v0.7.0` must be attributed to provider dispatch, protocol processing, copying, scheduling, or carrier behavior before #229 is considered complete.

## Interpretation boundary

This baseline establishes the pre-refactor software reference for VSPW-TP over UDP. It does not claim:

- raw-Ethernet performance;
- MCU/RTOS/DMA performance;
- SpaceWire controller or PHY timing;
- cable/link latency;
- timing equivalence between virtual transport and physical SpaceWire.

Those are separate evidence domains required by #230 as the corresponding providers become available.
