# VSPW-TP/UDP pre-refactor baseline

## Purpose

This record freezes the pre-#229 VSPW-TP/UDP performance boundary before the
transport-provider refactor separates VSPW session/reliability logic from the
UDP/socket carrier.

The baseline is intentionally tied to an immutable released tree so later UDP
provider measurements can distinguish protocol-engine cost from transport
abstraction and carrier cost.

## Hosted-screen configuration

The candidate VSPW/UDP comparison used:

- measurement domain: software;
- unit: architectural counter ticks;
- architecture: x86_64;
- compiler family: GCC;
- counter: x86 `RDTSCP`;
- backend: UDP;
- SpWKit path: VSPW-TP;
- native comparator: direct UDP socket;
- fixture: same-process loopback UDP;
- boundary: complete public API operation;
- per-iteration ordering: alternating SpWKit/native;
- counter floor: recorded, not subtracted;
- warmup: 32 iterations;
- measured iterations: 128;
- payloads: 0, 64, 1024 and 4096 bytes.

The 4096-byte row exercises the fragmented VSPW-TP path with the v0.7 default
1200-byte fragment payload.

## Post-refactor comparison rule

After #229 routes UDP through the transport-provider interface:

1. keep the same public VSPW/UDP behavior and packet/fragment configuration;
2. rerun the same native-relative TX/RX comparison;
3. preserve the 0/64/1024/4096-byte hosted screen for direct continuity;
4. run the normal controlled campaign with the broader release payload set;
5. isolate provider-dispatch cost separately where practical;
6. investigate any recurring regression before #229 is considered complete.

The relevant comparison is the cost added by the provider abstraction and
refactored protocol engine relative to this exact released tree. A raw-Ethernet
provider is evaluated separately and must not be used to conceal a regression
in the retained UDP path.

## Interpretation limits

This is a reproducible software regression baseline, not a physical SpaceWire
performance specification. GitHub-hosted absolute timing varies with host
placement and scheduler behavior. The immutable tree, benchmark inputs,
measurement boundary and repeated native-relative comparison are the durable
parts of this record.

Physical raw-Ethernet and embedded measurements required by #230 remain
separate evidence layers.
